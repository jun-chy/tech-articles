# Qt信号与槽机制深度解析：从moc到元对象系统

> 作者：蔡浩宇 | Qt开发笔记

## 引言

信号与槽（Signals & Slots）是Qt框架最具特色的机制，也是Qt区别于其他GUI框架的核心设计。它实现了对象间的松耦合通信——发送者不需要知道接收者的存在，接收者也不需要知道发送者的身份。本文将深入剖析信号槽的实现原理，从moc编译器到元对象系统，帮助读者建立对Qt底层机制的深刻理解。

---

## 1. 为什么需要信号与槽？

### 1.1 传统回调的局限

```cpp
/* 传统C风格回调 */
// 注册回调
button->setOnClickCallback(onButtonClicked);

// 回调函数
void onButtonClicked(void *user_data)
{
    // 需要手动类型转换和类型安全检查
    MyWindow *win = (MyWindow *)user_data;
    win->handleClick();
}
```

**问题**：类型不安全、紧耦合、不支持一对多。

### 1.2 信号槽的优势

```cpp
/* Qt风格 */
connect(button, &QPushButton::clicked,
        this,    &MyWindow::handleClick);
```

**优势**：类型安全（编译期检查）、松耦合、支持一对多/多对一、跨线程自动队列连接。

## 2. 信号槽基本语法

### 2.1 定义信号与槽

```cpp
class Counter : public QObject
{
    Q_OBJECT  // 必须包含这个宏！

public:
    explicit Counter(QObject *parent = nullptr) : QObject(parent), m_value(0) {}

    int value() const { return m_value; }

public slots:
    void setValue(int val)
    {
        if (val != m_value) {
            m_value = val;
            emit valueChanged(val);  // 发射信号
        }
    }

signals:
    void valueChanged(int newValue);  // 信号声明（只需声明，无需实现）

private:
    int m_value;
};
```

### 2.2 连接方式

```cpp
Counter a, b;

/* 方式1：函数指针（推荐，编译期类型检查） */
connect(&a, &Counter::valueChanged,
        &b, &Counter::setValue);

/* 方式2：旧式字符串连接（Qt5仍支持但不推荐） */
connect(&a, SIGNAL(valueChanged(int)),
        &b, SLOT(setValue(int)));

/* 方式3：Lambda表达式 */
connect(&a, &Counter::valueChanged, [&](int val) {
    qDebug() << "Value changed to:" << val;
});

/* 方式4：断开连接 */
disconnect(&a, &Counter::valueChanged,
           &b, &Counter::setValue);
```

## 3. moc编译器与元对象系统

### 3.1 编译流程

```
                  ┌──────────┐
  Counter.h  ──► │   C++     │ ──► Counter.moc.o
  (Q_OBJECT)      │  编译器   │
                  └──────────┘
                        │
  Counter.cpp  ──► ──────┘  ──► Counter.o
                        │
                        ▼
                  ┌──────────┐
                  │   链接器  │ ──► 可执行文件
                  └──────────┘

  moc做了什么？
  ┌─────────────────────────────────────────┐
  │  1. 解析 Q_OBJECT 宏标记的类            │
  │  2. 生成信号函数的实现代码              │
  │  3. 生成元对象信息（信号/槽/属性列表）  │
  │  4. 生成 qt_metacall / qt_static_metacall│
  │  5. 输出为 xxx.moc 或 moc_xxx.cpp 文件 │
  └─────────────────────────────────────────┘
```

### 3.2 moc生成的信号实现

moc 为 `valueChanged(int)` 信号生成如下代码（简化版）：

```cpp
// moc_counter.cpp (由moc自动生成)
void Counter::valueChanged(int _t1)
{
    void *args[] = { nullptr, &_t1 };
    QMetaObject::activate(this, &staticMetaObject, 0 /* signalIndex */, args);
}
```

`QMetaObject::activate()` 遍历该信号的所有连接，依次调用槽函数。

## 4. connect底层实现

### 4.1 QMetaObject::Connection

```cpp
/* connect的返回值是一个Connection对象 */
QMetaObject::Connection conn = connect(sender, &Sender::signal,
                                       receiver, &Receiver::slot);

/* 后续可断开 */
disconnect(conn);
```

### 4.2 连接类型

```cpp
/* 自动连接（默认）：同线程=直连，跨线程=队列连接 */
connect(sender, &Sender::signal, receiver, &Receiver::slot);

/* 强制直连：在发送者线程中执行槽函数 */
connect(sender, &Sender::signal, receiver, &Receiver::slot,
        Qt::DirectConnection);

/* 强制队列连接：在接收者线程的事件循环中执行 */
connect(sender, &Sender::signal, receiver, &Receiver::slot,
        Qt::QueuedConnection);

/* 唯一连接：避免重复连接 */
connect(sender, &Sender::signal, receiver, &Receiver::slot,
        Qt::UniqueConnection);
```

### 4.3 跨线程通信原理

```
  线程A (发送者)              线程B (接收者)
  ┌───────────────┐          ┌───────────────┐
  │ emit signal() │          │               │
  │       │        │          │  事件循环     │
  │       ▼        │          │  ┌─────────┐  │
  │ QMetaObject:: │  QEvent  │  │处理事件  │  │
  │ activate()    │─────────►│  │执行槽函数│  │
  │ postEvent()   │ 放入队列 │  └─────────┘  │
  └───────────────┘          └───────────────┘

  关键：跨线程时，Qt将调用封装为QEvent，
  通过事件循环投递到接收者线程执行。
  这就是为什么接收者所在线程必须有事件循环！
```

## 5. 实战：自定义信号槽通信

### 5.1 模型-视图通信示例

```cpp
// 数据模型
class SensorModel : public QObject
{
    Q_OBJECT
public:
    explicit SensorModel(QObject *parent = nullptr) : QObject(parent) {}

    void updateTemperature(float temp)
    {
        m_temperature = temp;
        emit temperatureChanged(temp);  // 数据变化时发射信号
    }

    float temperature() const { return m_temperature; }

signals:
    void temperatureChanged(float newTemp);

private:
    float m_temperature = 0.0f;
};

// 视图（UI组件）
class TemperatureDisplay : public QWidget
{
    Q_OBJECT
public:
    explicit TemperatureDisplay(QWidget *parent = nullptr) : QWidget(parent)
    {
        m_label = new QLabel("0.0 C", this);
        m_label->setAlignment(Qt::AlignCenter);
        m_label->setStyleSheet("font-size: 24px; color: #2196F3;");
    }

public slots:
    void onTemperatureChanged(float temp)
    {
        m_label->setText(QString("%1 °C").arg(temp, 0, 'f', 1));
    }

private:
    QLabel *m_label;
};

// 组装
int main(int argc, char *argv[])
{
    QApplication app(argc, argv);

    SensorModel model;
    TemperatureDisplay display;

    QObject::connect(&model, &SensorModel::temperatureChanged,
                     &display, &TemperatureDisplay::onTemperatureChanged);

    display.show();

    // 模拟数据更新
    QTimer::singleShot(1000, [&]() { model.updateTemperature(25.3); });
    QTimer::singleShot(2000, [&]() { model.updateTemperature(26.8); });

    return app.exec();
}
```

## 6. 性能注意事项

| 要点 | 说明 |
|------|------|
| 避免高频信号 | 每秒数千次信号发射会显著拖慢UI |
| 使用QSignalMapper | 多按钮映射时避免大量connect |
| 考虑直接调用 | 同步且高频场景下，直接调用比信号槽快10倍+ |
| 跨线程用队列 | 跨线程必须用QueuedConnection，否则线程不安全 |
| 断开无用连接 | 对象销毁前不需要手动disconnect，Qt自动管理 |

## 7. 总结

信号与槽不仅是Qt的"语法糖"，更是一个完整的元对象通信框架：

- **moc编译器**负责生成信号的实现和元对象信息
- **元对象系统**提供了运行时类型信息和反射能力
- **事件循环**是跨线程信号槽通信的基础
- **编译期类型检查**保证了连接的安全性

理解这些底层机制，有助于写出更高效、更可维护的Qt应用程序。
