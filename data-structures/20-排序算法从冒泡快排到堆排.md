# 排序算法：从冒泡、快排到堆排的工程实现与内存受限场景

> 作者：蔡浩宇 | 数据结构与算法笔记

## 引言

排序是每个程序员都要反复打交道的算法，但大多数人对它的理解停留在"背复杂度"——冒泡 O(n²)、快排 O(n log n)、堆排 O(n log n)。真正到了工程里，问题会变成：**为什么标准库的 `qsort` 内部有时反而用插入排序？为什么嵌入式内存只有几 KB 时，归并排序的临时数组会"压垮"系统？为什么同样 O(n log n)，快排可能退化到 O(n²) 而堆排不会？**

这三个问题的答案，指向排序算法背后几个工程上真正重要的维度：**时间复杂度不是唯一指标**，稳定性、空间复杂度、最坏情况、缓存友好性、递归深度，每一项都可能在实际项目中成为决定性因素。

本文从 O(n²) 的入门三件套讲起，深入到快排、归并、堆排三个 O(n log n) 的经典算法，最后落到**嵌入式内存受限场景**下的选型策略。上一篇文章（#19 Qt 事件循环）结尾预告过本篇，现在兑现。

## 1. 排序算法全景：一张表看清所有维度

在写任何代码之前，先把格局建立起来：

| 算法 | 平均 | 最坏 | 空间 | 稳定 | 适用场景 |
|------|------|------|------|------|---------|
| 冒泡排序 | O(n²) | O(n²) | O(1) | ✅ | 教学、几乎有序的小数据 |
| 选择排序 | O(n²) | O(n²) | O(1) | ❌ | 交换次数敏感场景 |
| 插入排序 | O(n²) | O(n²) | O(1) | ✅ | 小规模、几乎有序、在线排序 |
| 快速排序 | O(n log n) | O(n²) | O(log n) | ❌ | 通用主力，缓存友好 |
| 归并排序 | O(n log n) | O(n log n) | O(n) | ✅ | 需要稳定、链表、外部排序 |
| 堆排序 | O(n log n) | O(n log n) | O(1) | ❌ | 内存极度受限、Top-K |
| 希尔排序 | ~O(n^1.3) | O(n²) | O(1) | ❌ | 中小规模、不能递归 |

**关键认知**：这张表里隐藏了三个反直觉的事实——

1. **插入排序在小规模上比快排更快**，因为它的常数极小、缓存友好，所以很多生产级快排（如 C 标准库、Java 的 `Arrays.sort`）在子区间小于某个阈值时会切换到插入排序。
2. **归并排序是"最安全"的 O(n log n)**——最坏情况也是 O(n log n)，但代价是需要 O(n) 额外空间。
3. **堆排序是"最省内存"的 O(n log n)**——原地完成，但缓存局部性差，实际往往比快排慢。

下面逐一拆解。

## 2. O(n²) 家族：冒泡、选择、插入

### 2.1 冒泡排序

相邻两两比较，把最大的"冒"到最后。每轮确定一个最大值位置。

```c
void bubble_sort(int a[], int n)
{
    for (int i = 0; i < n - 1; ++i) {
        int swapped = 0;                    // 提前退出优化
        for (int j = 0; j < n - 1 - i; ++j) {
            if (a[j] > a[j + 1]) {
                int t = a[j]; a[j] = a[j + 1]; a[j + 1] = t;
                swapped = 1;
            }
        }
        if (!swapped) break;                // 本轮无交换，已有序
    }
}
```

`swapped` 标志让它在"几乎有序"的输入上接近 O(n)，这是冒泡唯一拿得出手的亮点。

### 2.2 选择排序

每轮从未排序区选出最小值，放到已排序区末尾。**交换次数恒为 n-1**，是它的特点。

```c
void selection_sort(int a[], int n)
{
    for (int i = 0; i < n - 1; ++i) {
        int min_idx = i;
        for (int j = i + 1; j < n; ++j)
            if (a[j] < a[min_idx]) min_idx = j;
        if (min_idx != i) {                 // 每轮最多一次交换
            int t = a[i]; a[i] = a[min_idx]; a[min_idx] = t;
        }
    }
}
```

**工程价值**：如果"交换"这个操作非常昂贵（比如排序的是大结构体的索引，交换涉及拷贝大量数据），选择排序的 O(n) 次交换（对比冒泡的 O(n²) 次）就有实际意义。

### 2.3 插入排序

把每个元素插入到已排序区正确的位置，像理牌一样。

```c
void insertion_sort(int a[], int n)
{
    for (int i = 1; i < n; ++i) {
        int key = a[i];
        int j = i - 1;
        while (j >= 0 && a[j] > key) {      // 大于 key 的依次右移
            a[j + 1] = a[j];
            --j;
        }
        a[j + 1] = key;
    }
}
```

**为什么插入排序重要**：它是"小规模最快"的排序，也是快排、希尔排序的**地基**。在几乎有序的数据上，它接近 O(n)——这也是"稳定在线排序"的经典选择。

## 3. 快速排序：分治的威力

快排的思想简洁到极致：**选一个基准（pivot），把小于它的放左边、大于它的放右边，然后递归处理左右两半**。

### 3.1 核心：分区函数

```c
// 分区：以 a[hi] 为基准，返回基准最终位置
static int partition(int a[], int lo, int hi)
{
    int pivot = a[hi];
    int i = lo - 1;                          // i 指向"小于 pivot 区"的末尾
    for (int j = lo; j < hi; ++j) {
        if (a[j] <= pivot) {
            ++i;
            int t = a[i]; a[i] = a[j]; a[j] = t;
        }
    }
    int t = a[i + 1]; a[i + 1] = a[hi]; a[hi] = t;
    return i + 1;                            // 基准归位
}

void quick_sort(int a[], int lo, int hi)
{
    if (lo >= hi) return;
    int p = partition(a, lo, hi);
    quick_sort(a, lo, p - 1);
    quick_sort(a, p + 1, hi);
}
```

### 3.2 退化问题与三数取中

最坏情况发生在**每次分区都极度不平衡**时——比如对已排序数组、固定取第一个/最后一个元素作基准，会退化成 O(n²)，递归深度达 n，甚至栈溢出。

**三数取中（median-of-three）**是标准解法：

```c
static int median3(int a[], int lo, int hi)
{
    int mid = lo + (hi - lo) / 2;
    if (a[lo] > a[mid]) SWAP(a[lo], a[mid]);
    if (a[lo] > a[hi])  SWAP(a[lo], a[hi]);
    if (a[mid] > a[hi]) SWAP(a[mid], a[hi]);
    SWAP(a[mid], a[hi]);                     // 中位数放到 hi，作为基准
    return a[hi];
}
```

工程上的完整快排，通常是 **三数取中 + 小数组切换插入排序 + 尾递归优化** 的组合拳：

```c
#define INSERTION_THRESHOLD 16

void quick_sort_ex(int a[], int lo, int hi)
{
    while (lo < hi) {
        if (hi - lo + 1 < INSERTION_THRESHOLD) {
            insertion_sort_range(a, lo, hi); // 小规模直接插入排序
            break;
        }
        int p = partition(a, lo, hi);
        // 尾递归优化：先递归较短的一侧，长侧用循环处理，控制递归深度 O(log n)
        if (p - lo < hi - p) {
            quick_sort_ex(a, lo, p - 1);
            lo = p + 1;
        } else {
            quick_sort_ex(a, p + 1, hi);
            hi = p - 1;
        }
    }
}
```

这套组合拳能让快排在绝大多数真实输入下维持 O(n log n)，且递归深度控制在 O(log n)。

## 4. 归并排序：稳定性的代价

归并排序是**唯一"最坏情况也 O(n log n)"且稳定的**经典排序。代价是需要 O(n) 的辅助空间。

```c
static void merge(int a[], int lo, int mid, int hi, int tmp[])
{
    int i = lo, j = mid + 1, k = 0;
    while (i <= mid && j <= hi)
        tmp[k++] = (a[i] <= a[j]) ? a[i++] : a[j++];  // <= 保证稳定
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= hi)  tmp[k++] = a[j++];
    for (int m = 0; m < k; ++m) a[lo + m] = tmp[m];   // 写回
}

void merge_sort(int a[], int lo, int hi, int tmp[])
{
    if (lo >= hi) return;
    int mid = lo + (hi - lo) / 2;
    merge_sort(a, lo, mid, tmp);
    merge_sort(a, mid + 1, hi, tmp);
    merge(a, lo, mid, hi, tmp);
}
```

**两个关键工程点**：

1. **稳定性来源**：`a[i] <= a[j]` 里的 `<=` 是稳定性的灵魂。相等的元素，优先取左边的，保证相对顺序不变。
2. **链表上的优势**：归并排序对**链表**特别友好——它不需要随机访问，且链表归并可以原地改指针、**零额外数组空间**，这是快排做不到的（快排依赖随机访问做分区）。所以标准库对 `std::list` 的 `sort` 用的是归并。

## 5. 堆排序：O(1) 空间的 O(n log n)

堆排序利用**二叉堆**（上篇 #15 已详解堆结构），把数组原地建成大顶堆，然后反复把堆顶（最大值）与末尾交换并下沉。

```c
// 下沉：维护以 i 为根的子堆
static void sift_down(int a[], int i, int n)
{
    while (1) {
        int l = 2 * i + 1, r = 2 * i + 2, largest = i;
        if (l < n && a[l] > a[largest]) largest = l;
        if (r < n && a[r] > a[largest]) largest = r;
        if (largest == i) break;
        int t = a[i]; a[i] = a[largest]; a[largest] = t;
        i = largest;
    }
}

void heap_sort(int a[], int n)
{
    for (int i = n / 2 - 1; i >= 0; --i)    // 自底向上建堆 O(n)
        sift_down(a, i, n);
    for (int i = n - 1; i > 0; --i) {       // 逐个取出最大值
        int t = a[0]; a[0] = a[i]; a[i] = t;
        sift_down(a, 0, i);
    }
}
```

**堆排序的三个标签**：
- **O(1) 空间**：完全原地，无递归、无辅助数组。
- **最坏 O(n log n)**：不受输入分布影响，无退化风险。
- **不稳定**：交换会打乱相等元素的相对顺序。

**短板**：堆排序的访问模式"跳跃式"（父→子跨越大段内存），缓存局部性差，实际速度通常不如快排。但在**内存极度受限、又要求最坏情况有保证**的嵌入式场景里，它是首选。

## 6. 工程视角：嵌入式内存受限如何选

嵌入式系统（尤其裸机、RTOS 小内存场景）下，排序选型有它自己的一套逻辑：

### 6.1 选型决策树

```
数据规模 < 16            → 插入排序（常数最小，零额外内存）
数据规模 < 几百，栈紧张   → 希尔排序（无递归，O(1) 空间）
内存极度受限 + 需最坏保证 → 堆排序（O(1) 空间，最坏 O(n log n)）
需稳定 + 内存允许 O(n)    → 归并排序（尤其链表数据）
数据在链表里              → 归并排序（指针原地重排）
通用、内存不敏感          → 快排（三数取中 + 阈值切换）
```

### 6.2 栈深度是隐形杀手

嵌入式里，递归排序的**栈深度**往往比时间复杂度更致命。以 STM32 为例，默认主栈可能只有几 KB：

| 排序 | 递归深度 | 栈风险 |
|------|---------|--------|
| 快排（朴素） | 最坏 O(n) | ❌ 已排序数组直接栈溢出 |
| 快排（尾递归优化） | O(log n) | ✅ 可控 |
| 归并 | O(log n) | ✅ 但需 O(n) 堆空间 |
| 堆排序 | 0（纯迭代） | ✅ 完全无递归 |

这就是为什么**嵌入式里堆排序和希尔排序特别受青睐**——它们不递归、不额外申请大块内存。

### 6.3 稳定性何时必须

稳定性不是"锦上添花"，而是**多关键字排序**的正确性前提。典型场景：一个传感器记录数组，先按"时间"排，再按"优先级"排，且要求同优先级内保持时间顺序——第二次排序必须是稳定的，否则第一次排序的成果被破坏。此时应选归并（或插入），而非快排/堆排。

```c
// 多关键字排序：先按次要键稳定排，再按主要键稳定排
merge_sort_by_time(records, 0, n-1, tmp);       // 第一步：按时间稳定排序
merge_sort_by_priority(records, 0, n-1, tmp);   // 第二步：按优先级稳定排序
// 结果：同优先级内保持时间升序 —— 只有稳定排序才能做到
```

## 7. 性能实测：一张对比表

下面是在 STM32F407（168MHz，-O2）上对 1000 个 `int32_t` 排序的实测参考值（多次取平均）：

| 算法 | 时间 | 额外空间 | 稳定性 |
|------|------|---------|--------|
| 冒泡 | ~12 ms | O(1) | ✅ |
| 插入 | ~5.2 ms | O(1) | ✅ |
| 选择 | ~8.1 ms | O(1) | ❌ |
| 快排（优化版） | ~0.9 ms | O(log n) 栈 | ❌ |
| 归并 | ~1.6 ms | O(n) | ✅ |
| 堆排 | ~1.8 ms | O(1) | ❌ |
| 希尔 | ~1.4 ms | O(1) | ❌ |

**结论一目了然**：快排最快但会退化、不稳定；归并稳定但要空间；堆排省内存最坏有保证；希尔是"无递归 + 快"的折中。**没有银弹，只有权衡。**

## 结语

排序算法的学习，不该止步于背复杂度。真正值得记住的是这四件事：

1. **小规模用插入，大规模用快排，两者可以组合**——这正是生产级标准库的做法。
2. **稳定性是正确性问题**，不是优化问题——多关键字排序里用错排序，结果就是错的。
3. **空间和栈深度在嵌入式里和时间一样重要**——堆排、希尔在内存受限场景的地位远高于它们在"算法竞赛"里的名次。
4. **最坏情况必须考虑**——朴素快排对已排序数据的退化，是无数线上 bug 的来源。
