# 堆与优先队列：从C语言实现到嵌入式任务调度

> 作者：蔡浩宇 | 数据结构与算法笔记

## 引言

上一篇我们讨论了BST与AVL树在有序数据管理中的优秀表现——O(log n)的查找、O(n)的有序遍历。但在很多场景下，我们并不需要"全排序"，只需要"每次取出优先级最高（或最低）的那个元素"。比如操作系统的任务调度器需要从就绪队列中挑出优先级最高的任务，网络路由器需要从待发送数据包中优先处理QoS标记最高的包。这些场景的共同需求催生了**优先队列（Priority Queue）**，而它的最佳底层实现就是**二叉堆（Binary Heap）**。

---

## 1. 从需求到数据结构

### 1.1 三种实现方案对比

| 实现方式 | 插入 | 取出最大/小 | 适用场景 |
|---------|------|-----------|---------|
| 无序数组 | O(1) | O(n) | 插入远多于取出 |
| 有序数组 | O(n) | O(1) | 取出远多于插入 |
| **二叉堆** | **O(log n)** | **O(log n)** | **插入与取出均衡** |

二叉堆是插入和删除都保持O(log n)的唯一简单结构，并且可以用数组紧凑存储，无需指针开销。

### 1.2 堆的定义

```
堆是一个完全二叉树，满足堆序性质：

最大堆（Max-Heap）：每个节点的值 ≥ 其所有孩子的值
         50
        /  \
      30    40
     /  \   /
   10   5  20

最小堆（Min-Heap）：每个节点的值 ≤ 其所有孩子的值
         5
        / \
      10   20
     /  \  /
   30  50 40
```

**完全二叉树**意味着：除最后一层外，每一层都是满的；最后一层的节点从左到右连续排列。这一性质使得堆可以用数组完美表示。

### 1.3 数组存储映射

```
索引规则（假设根节点在索引0）：
  • 节点 i 的父节点：      (i - 1) / 2
  • 节点 i 的左子节点：    i * 2 + 1
  • 节点 i 的右子节点：    i * 2 + 2

图示：
            0
          /   \
         1     2
        / \   / \
       3   4 5   6

数组：[A, B, C, D, E, F, G]
索引： 0  1  2  3  4  5  6
```

## 2. 核心操作：Sift-Up 与 Sift-Down

堆的全部魔法都凝聚在两个操作上：向上调整（sift-up）用于插入，向下调整（sift-down）用于删除。

### 2.1 Sift-Up（上浮）：插入操作

新元素放在数组末尾（完全二叉树的最后一个位置），然后与父节点比较并交换，直到堆序性质恢复。

```
插入 45 到最大堆 [50, 30, 40, 10, 5, 20]

Step 1: 放到末尾
         50
        /  \
      30    40
     /  \   / \
   10   5 20  45  ← 新元素

Step 2: 与父节点(40)比较 → 45 > 40，交换
         50
        /  \
      30    45
     /  \   / \
   10   5 20  40

Step 3: 与父节点(50)比较 → 45 < 50，停止
```

### 2.2 Sift-Down（下沉）：删除操作

堆顶元素被移除后，将最后一个元素移到堆顶，然后与较大的（最大堆）或较小的（最小堆）子节点交换，直到堆序性质恢复。

```
从最大堆中删除根节点 50

Step 1: 移除根，末尾元素顶上
         40  ← 原末尾元素
        /  \
      30    45
     /  \   /
   10   5 20

Step 2: 与子节点比较 → 45 > 40，与左子交换...等等，45在右边
         45
        /  \
      30    40
     /  \   /
   10   5 20

Step 3: 40 > 20，停止（已是叶子或满足堆序）
```

## 3. C语言完整实现（最小堆）

```c
// minheap.h
#ifndef MINHEAP_H
#define MINHEAP_H

#include <stddef.h>
#include <stdbool.h>

typedef struct {
    int *data;      // 数组存储
    size_t size;    // 当前元素个数
    size_t cap;     // 容量
} MinHeap;

MinHeap *heap_create(size_t cap);
void heap_destroy(MinHeap *h);
bool heap_push(MinHeap *h, int val);
bool heap_pop(MinHeap *h, int *out);
bool heap_peek(const MinHeap *h, int *out);
bool heap_is_empty(const MinHeap *h);
size_t heap_size(const MinHeap *h);

#endif
```

```c
// minheap.c
#include "minheap.h"
#include <stdlib.h>
#include <string.h>

#define PARENT(i)   (((i) - 1) / 2)
#define LEFT(i)     ((i) * 2 + 1)
#define RIGHT(i)    ((i) * 2 + 2)

MinHeap *heap_create(size_t cap) {
    MinHeap *h = malloc(sizeof(MinHeap));
    if (!h) return NULL;
    h->data = malloc(sizeof(int) * cap);
    if (!h->data) { free(h); return NULL; }
    h->size = 0;
    h->cap = cap;
    return h;
}

void heap_destroy(MinHeap *h) {
    if (h) {
        free(h->data);
        free(h);
    }
}

static void swap(int *a, int *b) {
    int t = *a; *a = *b; *b = t;
}

/* ============ 上浮 ============ */
static void sift_up(int *data, size_t idx) {
    while (idx > 0) {
        size_t p = PARENT(idx);
        if (data[idx] >= data[p]) break;
        swap(&data[idx], &data[p]);
        idx = p;
    }
}

/* ============ 下沉 ============ */
static void sift_down(int *data, size_t idx, size_t size) {
    while (1) {
        size_t smallest = idx;
        size_t left  = LEFT(idx);
        size_t right = RIGHT(idx);

        if (left < size && data[left] < data[smallest])
            smallest = left;
        if (right < size && data[right] < data[smallest])
            smallest = right;

        if (smallest == idx) break;  // 堆序正确
        swap(&data[idx], &data[smallest]);
        idx = smallest;
    }
}

/* ============ 插入 ============ */
bool heap_push(MinHeap *h, int val) {
    if (h->size >= h->cap) {
        // 扩容：×2策略
        size_t new_cap = h->cap * 2;
        int *new_data = realloc(h->data, sizeof(int) * new_cap);
        if (!new_data) return false;
        h->data = new_data;
        h->cap = new_cap;
    }
    h->data[h->size] = val;
    sift_up(h->data, h->size);
    h->size++;
    return true;
}

/* ============ 弹出堆顶 ============ */
bool heap_pop(MinHeap *h, int *out) {
    if (h->size == 0) return false;
    *out = h->data[0];
    h->data[0] = h->data[--h->size];
    sift_down(h->data, 0, h->size);
    return true;
}

bool heap_peek(const MinHeap *h, int *out) {
    if (h->size == 0) return false;
    *out = h->data[0];
    return true;
}

bool heap_is_empty(const MinHeap *h) {
    return h->size == 0;
}

size_t heap_size(const MinHeap *h) {
    return h->size;
}
```

**关键设计决策**：
- 使用`size_t`而非`int`作为索引类型，避免负数溢出
- 扩容采用×2策略，均摊复杂度O(1)
- `sift_up`和`sift_down`接受数组指针而非堆结构，便于复用（如堆排序）

## 4. 堆的应用№1：O(n)建堆与堆排序

### 4.1 建堆的两种策略

```c
/* 方法一：逐个插入（O(n log n)）—— 不推荐 */
MinHeap *h = heap_create(100);
for (int i = 0; i < n; i++)
    heap_push(h, arr[i]);

/* 方法二：从最后一个非叶子节点开始，逐个sift_down（O(n)）—— 推荐 */
void heapify(int *arr, size_t n) {
    // 最后一个非叶子节点索引 = (n/2) - 1
    for (ssize_t i = (n / 2) - 1; i >= 0; i--) {
        sift_down(arr, (size_t)i, n);
    }
}
```

**为什么方法二是O(n)？**

直觉上看似乎也是O(n log n)，但数学上：
- 树的高度为h = ⌊log₂n⌋
- 高度为i的节点最多有⌈n/2^(i+1)⌉个
- 每个节点下沉最多i次
- 总操作数 = Σ(i × n/2^(i+1)) ≈ n × Σ(i/2^(i+1)) < 2n

因此建堆是**严格的O(n)**，而非O(n log n)。

### 4.2 堆排序（升序 → 最大堆）

```c
void heap_sort(int *arr, size_t n) {
    // ① 建最大堆（将比较符号反转即可）
    for (ssize_t i = (n / 2) - 1; i >= 0; i--)
        sift_down_max(arr, (size_t)i, n);

    // ② 逐个取出堆顶（放到数组末尾）
    for (size_t end = n - 1; end > 0; end--) {
        swap(&arr[0], &arr[end]);     // 堆顶(最大值)放到已排序区
        sift_down_max(arr, 0, end);   // 对剩余元素重新建堆
    }
}
```

| 排序算法 | 平均时间 | 最坏时间 | 空间 | 稳定性 |
|---------|---------|---------|------|-------|
| 快速排序 | O(n log n) | O(n²) | O(log n) | 不稳定 |
| 归并排序 | O(n log n) | O(n log n) | O(n) | 稳定 |
| **堆排序** | **O(n log n)** | **O(n log n)** | **O(1)** | 不稳定 |

堆排序的唯一优势：**O(1)额外空间 + O(n log n)最坏保证**。在内存极度受限的嵌入式场景中，这是不可替代的选择。

## 5. 堆的应用№2：嵌入式任务调度器

在嵌入式RTOS（如FreeRTOS）中，任务调度器的核心是一个**基于优先级的就绪队列**。最小堆天然适合这一场景：

```c
// 任务控制块（简化版）
typedef struct {
    uint8_t  priority;   // 优先级（数字越小，优先级越高）
    uint32_t delay_ticks; // 剩余延时
    void   (*func)(void); // 任务函数
} TaskBlock;

// 按 "priority" 比较的最小堆
static int task_cmp(const TaskBlock *a, const TaskBlock *b) {
    return a->priority - b->priority;
}

// 调度器核心循环
void scheduler_run(MinHeap *ready_queue) {
    while (1) {
        TaskBlock task;
        if (!heap_pop(ready_queue, &task, task_cmp))
            break;  // 无就绪任务

        task.func();  // 执行当前最高优先级任务
        task.delay_ticks = task.default_ticks;
        heap_push(ready_queue, &task, task_cmp);  // 重新入队
    }
}
```

**与FreeRTOS实现的关系**：

FreeRTOS实际上用链表数组而非堆实现就绪队列——每个优先级一个链表，通过位图快速定位最高非空优先级（O(1)）。这种设计在优先级数量有限（≤32）且任务频繁切换时效率更高。但当优先级数量不固定或任务需要按"动态值"（如剩余时间片）排序时，堆是更优雅的选择。

## 6. 堆的变体与应用扩展

### 6.1 d-堆（d-ary Heap）

普通二叉堆每个节点2个子节点。当d > 2时：

| 属性 | 二叉堆 (d=2) | 四叉堆 (d=4) |
|------|-------------|-------------|
| 树高 | ⌊log₂n⌋ | ⌊log₄n⌋ |
| sift_down 比较次数 | ~2log₂n | ~4log₄n = ~2log₂n |
| 缓存局部性 | 较差 | **更好** |

四叉堆的树更"矮胖"，缓存的局部访问性更好。当数据量大到无法全部装入L3缓存时，d=4通常是最佳折中。

### 6.2 双端堆（Min-Max Heap）

支持**同时**在O(1)时间内获取最小值和最大值：

```
           1 (Min层)
        /      \
      50        2 (Max层)
     /  \      /  \
   30   40   10   20 (Min层)
```

交替层分别满足最小/最大堆性质。插入和删除仍为O(log n)。

### 6.3 实际工程选择

| 场景 | 推荐结构 |
|------|---------|
| 标准优先队列 | 二叉堆 |
| 大数据量、内存敏感 | 四叉堆 |
| 需要同时访问最大和最小 | 双端堆 |
| 需要合并两个优先队列 | 左偏堆 / 配对堆 |
| 需要降低已存在元素的键值 | 斐波那契堆（Dijkstra算法） |

## 7. 性能实测

在STM32F407（168MHz Cortex-M4）上，对以下操作进行1000次平均耗时统计：

| 操作 | n=100 | n=1000 | n=10000 |
|------|-------|--------|---------|
| heap_push | 2.1μs | 3.8μs | 5.6μs |
| heap_pop  | 3.4μs | 5.2μs | 7.1μs |
| heapify (建堆) | 68μs | 760μs | 8.2ms |

测试要点：
- 用DWT_CYCCNT捕获精确周期数，转换为微秒
- 开`-O2`优化（`-Os`在F4上反而更慢）
- 内存对齐到4字节边界以避免非对齐访问惩罚

## 结语

堆数据结构有一种精巧的数学美感：它用极简的数组表示和两个递归调整操作，实现了对数级别的高效优先队列。从STL的`std::priority_queue`到Linux内核的CFS调度器，从Dijkstra最短路径到Huffman编码——堆以其O(log n)的插入删除和O(1)的空间开销，成为算法工程中不可替代的基础构件。
